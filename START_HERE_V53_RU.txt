RNDM CHAT v53 — СРОЧНОЕ ОБНОВЛЕНИЕ БЕЗОПАСНОСТИ / АДМИНКА

Что сделано:
- Ник и отображаемое имя: максимум 15 символов.
- Название канала: 2–15 символов.
- Описания профиля и канала: максимум 50 символов.
- Все эти ограничения подтверждаются сервером Supabase, не только HTML.
- Существующие длинные записи оставлены нетронутыми, чтобы не ломать аккаунты и каналы.
- Серверная функция «не более 3 регистраций на IP» подготовлена и испытана в откатываемой тестовой транзакции. ОБЯЗАТЕЛЬНО активировать в Supabase Auth Hooks (см. ниже).
- В админке: точное время регистрации (Auth, UTC), очередь подозрительных событий, ручная проверка сообщений с причиной и журналом (только Owner), удаление аккаунта Auth (только Owner, с двойным подтверждением).
- Автоматические сигналы: повторяющийся спам, массовое создание каналов, несколько регистраций с одного IP (последнее — после включения Auth Hook).
- Снижена доступность приватных полей профилей другим аккаунтам.
- Запрошен добровольный отказ AI-краулерам через robots.txt и meta. Это НЕ техническая блокировка всех ботов.
- Прочие функции RNDM v52 сохранены.

УСТАНОВКА:
1. В корне GitHub-репозитория замени СТАРЫЕ файлы на содержимое данного ZIP без папок. Не смешивай версии JS.
2. Дождись завершения GitHub Pages и открой сайт в Safari заново.
3. В Supabase (rijqlmrcnshswtoweoai) открой Authentication → Hooks → Before User Created.
4. Выбери PostgreSQL Hook и функцию public.rndm_before_user_created, СОХРАНИ и ВКЛЮЧИ.
   Без этого переключателя ограничение 3 аккаунта на IP НЕ действует на новые регистрации.
5. Проверь через два РЕАЛЬНЫХ аккаунта чаты, клипы, профили, каналы и вход.

ВАЖНЫЕ ОГРАНИЧЕНИЯ:
- На общих сетях (CGNAT, публичный Wi-Fi) 3 человека могут делить один IP: последующим будет отказано в регистрации. VPN / мобильная сеть позволяет пользователю менять IP — абсолютной защиты от мультиаккаунтов нет.
- Исторические регистрации до включения хука не имеют IP-отпечатка в реестре; лимит учитывает только новые регистрации после активации.
- Owner может просматривать личные сообщения только через защищённый запрос с обязательной причиной и журналом. Это НЕ сквозное шифрование. Предварительно уведомляйте пользователей в правилах приватности.
- Удаление Auth через серверную функцию доступно только Owner. Может потребоваться ручная очистка файлов из Supabase Storage; удаление не стирает ранее сохранённые третьими лицами копии.
- Автоматические события — сигналы на РУЧНУЮ проверку, НЕ автоматическое доказательство вины.
- robots.txt / meta НЕ препятствуют недобросовестным парсерам и AI-ботам. При размещении GitHub Pages в подкаталоге robots.txt репозитория может НЕ находиться в корне домена и НЕ применяться.
- Полная DDoS-защита невозможна только с GitHub Pages + открытым Supabase API; нужны отдельные ограничения сети и WAF/прокси.
- Перед общедоступным запуском правила privacy.html должны пройти юридическую проверку.
- Работа функций на реальных двух аккаунтах и удаление аккаунта в production намеренно не тестировались, чтобы не трогать пользовательские данные.
