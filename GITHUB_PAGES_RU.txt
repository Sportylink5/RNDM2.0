RNDM Chat v52 — публикация на GitHub Pages без BAT и вложенных папок
=================================================================
1. Сохрани архив текущей рабочей версии перед обновлением.
2. Распакуй RNDM_Chat_v52_SECURITY_ADMIN_FLAT.zip на компьютере.
3. GitHub → твой репозиторий → Add file → Upload files.
4. Загрузи ВСЕ файлы из архива в корень репозитория: index.html, app.js,
   admin.js, style.css, sw.js, config.js, supabase-2.117.2.js и остальные.
   В архиве нет app/, assets/, vendor/ и вообще нет вложенных папок.
5. Нажми Commit changes. Замени существующие файлы с теми же именами.
6. Settings → Pages → Deploy from a branch → main → /(root) → Save.
   Если используется другая ветка, выбери её.
7. Дождись успешного развертывания и проверь сайт по URL Pages.
8. Если приложение установлено на домашнем экране iPhone, полностью закрой
   его и запусти заново. При ошибке несовместимой версии очисти кэш из
   интерфейса RNDM, но не удаляй свою учётную запись.

В config.js находится открытый publishable ключ Supabase, не secret.
Запрещено публиковать service_role, ключи Turnstile, токены Cloudflare,
пароли и банковские данные. Backend уже использует прежнюю базу данных.

После смены домена проверь в Supabase:
Authentication → URL Configuration → Redirect URLs:
https://ТВОЙ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/index.html
https://ТВОЙ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/reset-password.html?recovery=1

ДЛЯ МОДЕРАТОРА:
Админка → Публикации → Каналы → Создатель канала. Виден owner_id,
@username, имя, дата и ссылка на профиль. Доступ подтверждается Supabase.

ВНИМАНИЕ ПО БЕЗОПАСНОСТИ:
Этот ZIP не включает Cloudflare WAF. Без собственного домена нельзя настроить
управляемые правила. Прямая ссылка на Supabase API не защищена WAF домена.
Личные вложения в старом публичном Storage нужно переводить в закрытый бакет
по отдельному плану с миграцией, иначе ссылки остаются открытыми.
Подробности в SECURITY_AUDIT_V52_RU.txt и DDOS_CLOUDFLARE_V52_RU.txt.
