RNDM CHAT 33 — СЕТЬ ДЛЯ ЗВОНКОВ

Код аудио/видеозвонков подключён к прежним таблицам call_invites,
call_rooms и call_signals. Для обмена сигналами используются RPC:
invite_call, respond_call_invite, join_call_room_v2,
send_call_signal_v2, end_call_room_v2 и finish_call_invite.

Вызов входит и принимается без перехода на другую страницу.
Сигналы читаются по порядку; WebSocket будит чтение, опрос раз в секунду
страхует потерянные уведомления. ICE ожидает remoteDescription.
Каждая вкладка получает собственный идентификатор клиента.

Для проверки после публикации:
1. Войди двумя разными аккаунтами на двух устройствах.
2. На обоих открой HTTPS-ссылку GitHub Pages.
3. Позвони из личного чата и прими вызов на втором устройстве.
4. Проверь звук в обе стороны, выключение микрофона и завершение.
5. Для видео отдельно проверь камеру. Затем поменяй Wi-Fi на мобильную сеть.

TURN
STUN помогает найти прямой маршрут, но не пересылает медиапоток.
Если строгий NAT или оператор не позволяют прямое соединение,
потребуется TURN. В config.js можно заменить iceServers:

iceServers: [
  { urls: ['stun:stun.l.google.com:19302'] },
  {
    urls: ['turns:YOUR-TURN-HOST:443?transport=tcp'],
    username: 'YOUR-TEMPORARY-TURN-USERNAME',
    credential: 'YOUR-TEMPORARY-TURN-CREDENTIAL'
  }
],

Подставь действующие TURN-реквизиты от своего провайдера.
Поскольку статический config.js виден всем, используй только реквизиты,
предназначенные для клиентского подключения. Приватный API-ключ для
выдачи реквизитов и секретные ключи Supabase в config.js не размещаются.
Для постоянного публичного проекта лучше выдавать короткоживущие
TURN-реквизиты через сервер/Edge Function и обновлять их перед звонком.

Актуальная документация провайдера:
https://www.metered.ca/tools/openrelay/

Без TURN нельзя обещать звонки во всех сетях. База сигнализации
и GitHub Pages не заменяют TURN-сервер.
